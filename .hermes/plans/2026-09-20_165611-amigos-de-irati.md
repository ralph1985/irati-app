# Plan: menú «Amigos de Irati»

## Goal

Añadir una pestaña autenticada «Amigos» que muestre el listado inicial de familias y nombres de amigos de Irati, agrupado por procedencia y disponible también en la copia offline.

## Current context / assumptions

- Repositorio objetivo: `/home/rafa/dev/irati-app`, rama `main`; el estado previo a la implementación debe comprobarse con `git status --short --branch`.
- Stack verificado: Next.js 16.3.3, React 19.2.4, TypeScript, pnpm, Vitest, Supabase remoto y Dexie para la copia offline.
- La arquitectura existente separa `domain`, `application`, `infrastructure` y `ui` dentro de `src/modules/*`.
- La navegación online está en `src/app/(app)/_components/app-shell.tsx`; la navegación y el enrutado de la copia offline están duplicados deliberadamente en `src/shared/infrastructure/offline/offline-local-app.tsx`.
- Las pantallas privadas comprueban `hasValidSession()` antes de leer datos. Las tablas privadas de Supabase usan RLS y no conceden acceso a `anon` ni a `authenticated`; las lecturas pasan por el servidor con el cliente de Supabase existente.
- El roadmap está en el hito 22. Este cambio será un nuevo hito pequeño posterior, sin modificar el alcance de peso, vacunas, sueño, viaje o calendario.
- El listado aportado contiene 24 entradas de familia, 31 nombres de niños y 7 grupos visibles si la entrada sin encabezado se presenta como «Sin grupo»: Kamikazes (12), Palomares (4), Sin grupo (1), Meco (1), BBVA (1), Toledo (4) y Belmontejo (1).
- La entrada de familia es la unidad mínima del MVP. Cada registro conservará tres valores: grupo, texto de adultos/contexto y texto de niños. No se crea una tabla de personas, porque no hace falta para consultar el listado y obligaría a resolver identidades, duplicados y relaciones que el usuario no ha pedido.
- El MVP será de solo lectura: no habrá alta, edición, borrado, fotos, notas, buscador ni filtros. La persistencia será Supabase para que los datos no vivan en código y entren en backups; la copia offline será de lectura.
- Se conservarán literalmente los nombres, acentos, mayúsculas, paréntesis y textos contextuales proporcionados por el usuario. No corregir «Yulian», no traducir etiquetas y no deduplicar nombres repetidos entre familias.
- La línea `Maricruz y Diego` no tiene encabezado en la entrada original. Se almacenará con `group_label = null` y la UI la mostrará bajo «Sin grupo», conservando su posición entre Palomares y Meco. Si el usuario decide otro grupo, será un cambio de datos posterior, no una reinterpretación silenciosa durante esta tarea.
- Los nombres son datos familiares privados. No copiar el listado completo a documentación pública, tests innecesariamente amplios, logs ni mensajes de commit. La migración de seed sí debe contener exactamente los valores proporcionados para que la aplicación funcione.

## Architecture / proposed approach

Crear un módulo `src/modules/friends/` con una entidad de lectura `FriendEntry`, un caso de uso `listFriends`, un adaptador Supabase cacheado y un componente presentacional reutilizable. La tabla `friend_entries` tendrá una clave textual estable, `group_label` nullable, dos textos visibles y `sort_order`; así se preserva el formato del listado sin sobre-modelar personas.

Añadir `/amigos` al shell online y al shell offline. El endpoint de snapshot, Dexie y el exportador de backups incorporarán los registros, pero no se añadirá cola de mutaciones porque la primera versión no permite escribir desde la UI.

```ts
export type FriendEntry = {
  id: string;
  groupLabel: string | null;
  adultsLabel: string;
  childrenLabel: string;
  sortOrder: number;
};

export type FriendGroup = {
  label: string;
  entries: FriendEntry[];
};

export function groupFriendEntries(entries: FriendEntry[]): FriendGroup[] {
  const groups = new Map<string, FriendGroup>();

  for (const entry of [...entries].sort((first, second) => first.sortOrder - second.sortOrder)) {
    const label = entry.groupLabel ?? "Sin grupo";
    const group = groups.get(label) ?? { label, entries: [] };

    group.entries.push(entry);
    groups.set(label, group);
  }

  return [...groups.values()];
}
```

## Tests / validation

Cada bloque de código sigue el ciclo TDD donde aporta valor: crear primero el test mínimo, ejecutar el test para observar el fallo esperado, implementar la solución mínima, repetir el test enfocado y después ejecutar la suite relevante. Los bloques de documentación, migración SQL, navegación y backup se validan con sus comandos estáticos y con la integración final porque no tienen una unidad pura equivalente.

Suite mínima del módulo:

```bash
pnpm exec vitest run src/modules/friends
```

Suite completa requerida por `AGENTS.md`:


No ejecutar `pnpm exec supabase db push` ni generar backups remotos durante la planificación. Durante la implementación, ambas acciones requieren autorización para afectar estado externo y deben verificarse leyendo el estado resultante.

## Risks, tradeoffs, and open questions

- **Datos personales:** el seed contiene nombres reales de familiares/amigos. Mantenerlo en la migración privada y en Supabase; no repetirlo en documentación, fixtures públicos, logs, capturas ni commits descriptivos.
- **Entrada sin grupo:** se propone «Sin grupo» para `Maricruz y Diego` porque la fuente no aporta encabezado. Pregunta abierta: ¿debe asignarse posteriormente a Palomares u otro grupo?
- **Modelo deliberadamente simple:** adultos y niños se guardan como textos, no como personas normalizadas. Es suficiente para recordar nombres y evita duplicados/relaciones artificiales; si más adelante se necesita foto, ficha individual, búsqueda o edición, habrá que diseñar una migración separada.
- **Solo lectura inicial:** no hay CRUD porque el usuario ha pedido guardar este listado «de momento». Si se necesita editarlo desde la app, habrá que añadir casos de uso, acciones autenticadas, validación, invalidación de cache, mutaciones offline y tests de conflictos.
- **Offline:** se incluye lectura offline porque la app ya trata el snapshot como copia privada de todas las áreas principales. No se añade escritura offline; el contenido remoto sigue siendo la fuente compartida.
- **Aplicación remota:** `supabase db push` es una acción externa. Debe ejecutarse solo con autorización explícita y verificarse con `migration list --linked` y la lectura autenticada de `/amigos`.
- **Migración pendiente del hito 22:** el repositorio documenta aún validaciones remotas pendientes de Medidas. No mezclar esa migración ni sus registros con `friend_entries`; revisar la lista de migraciones antes de aplicar cualquier cambio.
- **Orden de navegación:** añadir una novena pestaña puede aumentar el desplazamiento en móvil. El shell existente ya usa scroll horizontal; si la prueba manual muestra mala discoverability, la alternativa futura es agrupar Amigos dentro de Ajustes, pero no cambiar esa decisión dentro de este primer alcance.
